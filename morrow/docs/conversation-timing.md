# 停顿与点评恢复

## 问题与原因

“辅导回复格式异常”来自教练返回内容的 JSON 解析，不表示用户的发音或表达错误。此前解析使用首个到最后一个花括号截取，混入带 JSON 的思考片段时容易失效；所有角色共用 650 token 输出上限，也可能使较长点评截断。截图对应的原始返回未留存，无法断定那一次具体属于哪种情况，不记录用户原话来追查。

抢答的已确认原因是 MiniMax 录音静音阈值原为约 900ms，口语练习中短暂停下来想词也可能触发切句。浏览器识别原来还把服务的 `onend` 直接当作整轮结束，不给续说留窗口。

## 用户设置

对话页右上角设置 → **语音与偏好 → 停顿多久后接话**，选择后点“保存设置”：

| 选项         | 用途                         |
| ------------ | ---------------------------- |
| 2 秒         | 较快轮流接话                 |
| 3 秒（默认） | 给普通句中思考留时间         |
| 5 秒         | 慢慢组织句子、容易停下来找词 |

旧版本没有该字段时自动使用三秒；已保存的合法档位刷新后保留。继续说话会重新计算等待时间。若希望确认后再发，可关闭原有的“停说后自动发送”，转写保留在输入框。

这是基于静音和识别事件的判断，不能知道用户在语义上是否已经说完；停顿超过所选时长仍可能结束当前轮。单轮最长六十秒，初始没有有效发言最长十秒；底层权限或识别错误可能更早结束并提示。

## 实现

- `speechTiming.ts` 集中定义 2 / 3 / 5 秒与异常设置回退；`Settings.speechPauseMs` 复用现有 `morrow:settings` 存储，无新存储键。
- MiniMax `SpeechBoundaryDetector` 按音量检测持续发声后静音，默认三秒。发声更新最后活动时间，静默期间继续保留麦克风；到边界后停止录音并释放轨道，再转写。
- `BrowserRecognition` 使用 continuous / interim 模式，按发声和转写事件等待。底层提前结束非空片段时，在同一轮内尝试继续识别，将多个片段合成一条转写；最终只提交一次。原生结果累计快照使用替换，避免 interim / final 重复追加。
- 浏览器片段重开保留原静默截止，不因空片段反复延长。暂停、挂断、后台和卸载取消重启与等待定时器；权限 / 设备失败保留已经识别的草稿。返回前台仍由媒体会话策略决定是否恢复。
- 浏览器能力仍由实际设备控制；不支持续识别时应提示并保留草稿，而不是无限开麦。当前设置不代表跨所有浏览器都能精确按秒切句。

## 点评与提示

`requestCoachCompletion` 统一用于灵感、点评和独立重练：

| 请求        | 首次输出预算 | 唯一一次格式重试预算 |
| ----------- | ------------ | -------------------- |
| 灵感提示    | 1200 token   | 2000 token           |
| 点评 / 重练 | 1800 token   | 2800 token           |

主回复仍为原输出预算。两次教练尝试共用三十五秒总期限；仅 JSON / 字段校验或明确 `finish_reason: length` 触发一次格式重试。鉴权、限流、网络、超时及主动取消不重试。格式重试沿用原上下文，不追加用户消息，不重新生成主回复，不将坏回复传给模型；可能产生一次额外调用额度。

解析器接受唯一完整对象、规范 JSON 围栏、完整思考块前后的结果和不含额外对象的说明文字，尊重字符串转义与括号。歧义多对象、未闭合片段、非法 JSON 和不符合字段类型的结果仍拒绝，不用 eval 或猜测补齐原文。不强迫未知兼容供应商接受专有 JSON 参数。

新用户发言开始时清除旧点评。当前点评失败不会显示上一句话的肯定或改进；等待 / 失败状态保留在下区，对话可以继续。两区的独立取消和版本控制不变。

## 验证与边界

自动测试覆盖句中两秒停顿、续说重新计时、五秒档、跨浏览器片段合并、重复转写防护、长轮次、初始无话、重启失败、挂断 / 后台 / 迟到事件、旧设置迁移、格式修复、截断、取消、总超时及新旧点评隔离。

真实 MiniMax 用虚构句子验证了点评和提示成功。验证中也曾遇到一次提示经过格式重试仍未通过，说明不能承诺所有模型调用都稳定符合约定；失败入口保留供用户重试。尚未实测用户麦克风、环境噪声、蓝牙或浏览器真实发声事件，不能把模拟时间测试当成硬件验收。
