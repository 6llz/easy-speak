# 项目优化记录与优先级

检查日期：2026-10-18。本轮保留移动端单屏对话与两个固定辅导框，优先修复实际问题、减少首屏负担，没有新增依赖或公开部署。

## 已完成

| 问题                   | 原因                                                                    | 现在的行为                                                                       |
| ---------------------- | ----------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| 换音色后仍叫 Alex      | 页面和角色提示使用固定名字                                              | 名字、状态、重听和后续角色提示跟随预设；已有消息保存当时称呼                     |
| 主回复重试后慢点评卡住 | 重试递增整轮版本，独立点评的结果与加载清理均被作废                      | 同轮主回复重试保留版本，点评正常完成，不重复用户消息                             |
| 教练重试留下无用请求   | 只隔离过期结果，没有取消同角色旧请求                                    | 同角色只保留最新请求，另一教练和主回复继续；仍保留版本防护                       |
| 错题可能误存凭据等设置 | `LanguagePair` 是结构类型，传入完整 `Settings` 后展开对象会带上额外字段 | 写入逐字段白名单，首屏与读取时清理旧记录，失败提示；复习对象也只接收规范语言字段 |
| 模型撤回纠错后错题仍在 | 无需纠正直接返回，未移除同消息旧记录                                    | 最新点评为自然表达时删除过期错题，其他记录不受影响                               |
| 次要功能占用首屏脚本   | 设置、课程、历史和收藏全部静态导入                                      | 首次进入对应功能才加载，等待和失败有局部关闭 / 重试入口                          |

修复错题的类型边界问题同时补入开发规范：持久化必须明确选择字段，不能把 TypeScript 的参数类型当作运行时过滤器。回归使用虚构凭据，没有把真实凭据写入测试或日志。迁移不能撤回此前可能被其他程序读取或自行导出的旧数据。

## 首屏构建对比

同一本地生产构建工具的主入口 JS 结果；基线为完成名字联动、尚未按需拆分时的构建。

| 指标           | 拆分前    | 本轮最终构建 | 减少               |
| -------------- | --------- | ------------ | ------------------ |
| 主入口 JS      | 400.32 KB | 353.49 KB    | 46.83 KB，约 11.7% |
| 主入口 JS gzip | 126.82 KB | 114.87 KB    | 11.95 KB，约 9.4%  |

设置约 23.49 KB、学习中心约 19.99 KB、记录 / 收藏约 7.51 KB 改为独立模块；公共小图标另有共享块。整体应用功能没有减少，首次访问这些功能仍需要加载模块。公共 CSS 保留在首屏，避免主题和布局样式延迟。以上是产物体积，不是手机实测加载时间或语音延迟。

`DeferredFeature` 将等待和错误限制在当前功能内，重新尝试建立新的懒加载实例，取消后迟到模块不会重新打开界面。对话组件始终挂载，原媒体暂停与结束意图保持；没有把整个 App 放入一次性全屏等待状态。

## 验证

- 全部 147 项自动测试通过，涵盖名字联动、历史兼容、主回复 / 教练独立恢复、取消与迟到结果、虚构凭据白名单、旧记录清理和功能加载失败恢复。
- 三项并发回归在修复前复现失败，修复后通过；不是仅验证静态代码结构。
- 严格 TypeScript、ESLint、Prettier 与生产构建通过。受限测试运行器启动失败后，在获准本机环境运行同一套离线测试，没有修改运行器。
- 本地页面、新模块与 MiniMax 状态接口返回 HTTP 200；扫描十个生产文件，未发现当前配置的服务端凭据。没有为本轮优化重复调用付费模型。
- 自动浏览器视觉与实际手机媒体验收仍未完成；已有工具限制见 [验证记录](./verification.md)。未把内存测试当成麦克风、摄像头、蓝牙或软键盘的真机验证。

## 后续优先级

1. **手机端语音实测与 HTTPS 访问。** 核心体验首先要测停说到转写、主回复首字和首音的时间，以及弱网、蓝牙、切后台和系统权限恢复。手机访问本机服务需要单独设计带鉴权的 HTTPS 接入；当前回环代理继续保持本机边界。
2. **本地备份与恢复。** 课程、收藏、错题和复习排期值得增加一个学习数据备份文件，导入先校验、预览、去重，排除凭据；避免清理浏览器或换手机后失去积累。入口宜收在“我的”，保持聊天页简洁。
3. **独立学习活动账本。** 当前统计来自最多一百条会话快照，删除历史会改变累计值，跨午夜长会话也按最后保存日归属。长期成长应改为可去重的每日事件账本，再处理留存和迁移。
4. **逐步拆分会话编排。** `usePractice` 仍承担较多职责。下一步可在既有生命周期回归保护下，分离请求任务管理、会话快照和媒体编排；不宜一次性重写状态机。多人账户、同步和配额留给有鉴权的服务端实现。

详细规则见 [功能说明](./features.md)、[架构](./architecture.md)、[学习功能](./learning.md) 和 [音色](./voices.md)。
