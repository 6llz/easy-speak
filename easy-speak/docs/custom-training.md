# 自定义训练

入口：对话顶部场景选择 → “今天想聊点什么？” → **自定义训练**。挑战页面及导航已移除；学习中心保留课程、对话、复习、我的四项导航，自定义训练不占导航位置。

## 使用

在“你想怎么练？”里自由描述要求，场景、角色、内容和提问方式均由用户决定，不预设分类。例如：

> 请当我的面试官，根据附件里的简历逐个提问。先问项目经历，再追问我的职责和解决问题的过程。

也可以写“陪我练一次酒店入住”“根据这篇文章问我观点”“让我在回答里用到这些单词”。可以只提供文字，也可以只添加材料，让语伴围绕材料开始交流。

1. 输入训练要求，或粘贴 / 上传参考材料。
2. 文件或图片读取后先显示预览，可修改、放弃或明确采用；采用会替换当前材料。正在编辑的内容不被迟到的读取结果覆盖。
3. 点击“开始训练”，使用当前两种语言、难度、供应商和音色生成开场，随后沿用原来的半双工语音对话。
4. 中间上区帮助回答当前问题，使用同一训练上下文；下区仍只点评最新用户发言的语言表达，不把文章知识问答当作语言错误。

无需先保存。展开“训练名称与我的模板”可命名、选择、编辑或删除模板；只有点击“保存模板”才写入本地。最多二十个模板，满额后允许更新已有模板，新增需先删除旧模板，不自动挤掉旧内容。删除模板不删除已生成的对话记录。

## 文件与图片

| 内容                  | 处理方式                                         | 边界                                                |
| --------------------- | ------------------------------------------------ | --------------------------------------------------- |
| TXT、Markdown、CSV    | 本机解码为纯文本，支持 UTF-8、带 BOM 的 UTF-16   | CSV 保留文字，不运行公式或 HTML                     |
| PDF                   | 本机按页抽取文字                                 | 最多六十页；扫描件 / 加密文件需转文字或使用页面图片 |
| DOCX                  | 本机提取纯文本                                   | 不支持旧 `.doc`；限制 ZIP 目录声明的展开体积        |
| PNG、JPG / JPEG、WebP | 本机缩小，再发送给当前模型读取可见文字及画面内容 | 需要支持图片的模型；输出预览供用户检查，不保存原图  |

单文件最多 8 MiB，训练要求最多三千字符，要求与材料合计最多二万四千字符。文档超限明确拒绝，不截断后当成完整材料。图片最大二千四百万像素，长边缩到一千六百像素后合成 JPEG，处理后最大 2 MiB；识别达到模型输出上限时提示拆分，不接受半截结果。图片尺寸缩小、复杂排版、手写和模糊内容可能影响理解，采用前应检查预览。

文档读取在本机进行；**选择图片时就会调用当前模型，并消耗对应额度**，界面在上传处说明。开始训练后，要求与材料文字会发送给当前选定供应商。图片不经过额外第三方图床，不静默切换供应商；已知不支持看图的配置会直接提示更换模型。当前本机 MiniMax-M3 图片路径已经最小实测，其他兼容接口还取决于实际模型能力和 CORS。

导入期间或尚未采用预览时，开始 / 保存按钮禁用；可取消读取。重新选文件、编辑或清空材料、新建训练、打开模型设置、关闭和卸载都会中止旧读取并隔离迟到结果。模型设置可从材料区进入，返回后保留草稿。

## 数据与模型上下文

`morrow:custom-trainings` 保存模板的 ID、名称、自由要求、材料文字、文件名与创建 / 更新时间。写入和读取均逐字段构造，凭据、语言设置、原文件、图片数据 URL 不进入模板。语言与供应商在每次开始时使用当前配置。存储失败明确提示，当前草稿仍可使用。

`Scene.training` 只保留当前训练的独立快照；改模板不会改变正在进行的训练。历史会话仅保存场景标识、标题和已产生的对话文字，不另存完整训练要求 / 材料；原文件和图片不进入长期记录。未保存模板在刷新或关闭后不保证恢复，模型回复中引用的材料可能随对话文字保留。

提示中将训练要求与 `REFERENCE_DATA_JSON` 参考材料分别引用：用户要求用于组织练习，材料中的命令和角色标签作为文档内容处理。模型缺少资料时应询问澄清，不编造个人经历或文章事实；这是模型行为约束，并非对所有提示注入的绝对保证。

自定义训练始终由真实模型生成开场，包括默认中英组合；无连接时不能用无关的本地示范回答。更换场景或语言会取消旧请求，两个教练继续遵循独立更新规则。完整材料随主回复及提示请求使用，尚未采用检索式分块，过长内容宜拆成多次训练。

## 工程与验收

- `lib/customTraining.ts`：模型、白名单、模板 CRUD、场景及提示上下文。
- `lib/trainingImport.ts`：本机文件读取、图片理解、体积边界与取消。
- `lib/docxContainer.ts`：ZIP 结构一致性与实际解压计量，单项 16 MiB / 总 32 MiB。拒绝伪造大小、重叠 / 重名 / 跳转路径、加密或不支持的压缩；设备缺少 raw deflate 解压能力时明确提示另存 TXT，不回退到无实际计量的解析。
- `CustomTrainingDialog`：自由文本、附件预览和折叠模板；从场景弹窗按需载入。PDF.js、Word 解析器和 PDF worker 也按需加载，不进入首屏主脚本。
- 图片沿用既有 Chat Completions 路由，使用 `image_url` 内容块，保留超时、取消和安全错误。代理聊天正文最大 4 MiB，朗读仍为 128 KiB，录音仍为 20 MiB；来源和凭据边界不变。
- PDF.js / Word 解析库缓存和依赖位于 D 盘。`npm audit` 当前报告 Mammoth CLI 的 `argparse → sprintf-js` 三项中危关联；应用只使用浏览器 bundle，构建不含这两个 CLI 模块，未采用强制降级。后续升级仍需复查。

验收重点：四项导航无挑战；场景弹窗有独立自定义入口；不显示分类表单；纯文字、仅材料、图片确认均能开始；切换材料 / 关闭后的旧结果不回写；保存失败不假成功；没有模型时可打开设置保留草稿；实际手机需检查软键盘、长材料滚动、文件选择器和语音续接。

协议来源：[MiniMax 多模态输入](https://platform.minimax.cn/docs/api-reference/text-openai-api)、[PDF.js 文档](https://mozilla.github.io/pdf.js/examples/index.html)、[Mammoth 纯文本接口](https://github.com/mwilliamson/mammoth.js#extracting-raw-text)。
